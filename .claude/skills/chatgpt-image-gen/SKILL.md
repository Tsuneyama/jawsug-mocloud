# ChatGPTで画像を生成する

ユーザーが契約しているChatGPT Plusで画像を生成し、生成された画像だけをダウンロードして保存する。
使うたびに `LOG.md` へ結果を記録し、`prompts.md` のひな形を改善する。

## 前提（毎回確認する）

1. **ブラウザ操作ができる環境か。** Claude in Chrome拡張のツール（タブ操作・クリック・入力・スクリーンショット）が使えること。
   - クラウドセッション（claude.ai/code）では `/chrome` が使えず、ユーザーのChromeを操作できない（2026-09-28に確認）。その場合は、ユーザーのPCで動くClaude Code（CLI / Desktop / VS Code）で実行してもらう。
   - PCでの有効化：`claude --chrome` で起動するか、起動後に `/chrome` を実行する。`/chrome` の画面で「Status: Enabled」「Extension: Installed」なら接続できている。常に有効にするなら `/chrome` で「Enabled by default」を選ぶ。
   - 条件：Anthropicの個人プラン（Pro / Max / Team / Enterprise）で `/login` していること（APIキー認証では使えない）。Chrome拡張は1.0.36以上。WSLでは使えない。
   - 操作できない場合は、`prompts.md` の指示文をユーザーに渡し、手動で生成してもらう（方式B）。
2. **ログインはユーザー自身が済ませておく。** パスワードや認証コードを受け取ったり入力したりしない。ログイン画面が出たら止めてユーザーに頼む。
3. **使うのは専用プロジェクトだけ。** ChatGPTは他のプロジェクトでも使われている。下の専用プロジェクト以外の会話を開かない・読まない・書かない。

## ChatGPT側の構成

- **場所：** ChatGPTの「プロジェクト」機能で、専用プロジェクト **「OCEALITE 画像生成」** を使う。無ければユーザーに作成を頼むか、許可を得て作成する。
- **プロジェクトの指示：** `prompts.md` の「プロジェクト指示」をそのまま設定する。スタイルの前提を毎回書かずに済み、他プロジェクトの文脈も混ざりにくい。
- **記憶：** 設定できる場合は、記憶の範囲をプロジェクト内に限定する。
- **モード：** 通常のChatを使う。画像生成は「指示 → 生成 → 修正指示」の短いやり取りなので、Work等の長時間タスク向けモードは使わない。
- **1画像＝1会話：** 画像ごとに新しい会話を作る。前の画像のスタイルが混ざるのを防ぐ。

## 手順

1. `prompts.md` から該当する指示文を選ぶ（無ければひな形から作り、先にユーザーへ見せる）。
2. ChatGPTの専用プロジェクトを開き、新しい会話を作る。
3. 指示文を貼って送信する。
4. 生成が終わるまで待つ。画像生成は1〜2分かかることがあるので、スクリーンショットで完了を確認してから次へ進む。
5. **生成された画像だけ**をダウンロードする。画像を開き、ダウンロードボタンを使う。ページ全体の保存やスクリーンショットで代用しない。
6. 画像を確認する（下のチェックリスト）。NGなら同じ会話で修正指示を出す。修正は最大3回まで。それでも駄目なら、指示文の問題として記録し、ユーザーに相談する。
7. ダウンロードした画像はChromeのダウンロードフォルダに入る。そこから、ファイル名を `YYYYMMDD-<用途>-v<番号>.png` に変更して保存先（既定：`docs/ocealite-organization-os/images/concept/`）へ移す。
8. `LOG.md` に記録する。うまくいった書き方・失敗した書き方は `prompts.md` に反映する。

## 確認チェックリスト

- 画像の中に文字が入っていない（または指示した文字が正しい）。日本語の文字は崩れやすいので、原則として文字を入れない。
- 人物が特定の実在人物や企業に見えない。ロゴや商標が入っていない。
- OCEALITEの色とトーン（`prompts.md` のスタイル）に合っている。
- 伝えたいこと（人が未来を決め、AIが実現する など）が一目で分かる。

## 使い分け

- **ChatGPTの画像生成：** 世界観・コンセプトを伝えるイメージ画像（表紙、章扉、スライドの背景など）。
- **HTML図解（`docs/ocealite-organization-os/images/src/`）：** 文字や構造を正確に見せる図。構成図・役割表などはこちらで作る。

## 改善のルール

- 毎回 `LOG.md` に「指示文・結果・修正回数・気づき」を残す。
- 同じ失敗が2回起きたら、`prompts.md` のひな形か、このSKILL.mdの手順を直す。
- 手順を変えたら、その理由を `LOG.md` に書く。
